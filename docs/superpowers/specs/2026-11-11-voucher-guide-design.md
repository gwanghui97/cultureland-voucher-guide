# 컬쳐랜드 "어디서 쓰지?" 사용처·사용법 길잡이 — 설계 문서

- 작성일: 2026-11-11
- 제출 마감: **2026-11-12 18:00** (컬쳐랜드 사전 미션, 개인)
- 심사 기준 원문: `guidelines-and-evaluation-criteria.pdf`, 요구사항: `functional-requirements.pdf`

## 1. 의도와 이유

모바일 문화상품권을 이벤트·선물로 받은 20대 대학생이 네이버쇼핑에서 쓰려다 막힌다.
"번호만 넣으면 결제되겠지"라고 생각하지만 실제로는 ① 상품권 종류 구분 → ② 컬쳐캐쉬 충전 →
③ Npay 포인트 전환(수수료) → ④ 네이버쇼핑 결제를 거쳐야 한다. 등록 시 번호 미인식, 전환 수수료에서 혼란.

**핵심 문제**: 사용처 부족이 아니라 "내 상품권을 어디서 어떤 절차로 쓰는지" 직관적으로 알 수 없음.
**핵심 가치**: 사용처 검색이 아니라, *보유 상품권 종류에 따라* 올바른 사용 경로를 찾아주는 길잡이.

## 2. 목표 / 비목표 / 반목표

**목표**
- 입력(사용처) → 상품권 종류 확인 → 가능 여부·조건 → 맞춤 사용 방법까지 끊김 없는 클릭형 시제품.
- 네이버쇼핑(온라인) 전체 흐름 + CU(오프라인) 비교 흐름.
- 모든 정책 수치에 출처명·확인일·원문 링크 표시. 미확인 정보·검색 결과 없음 안내.
- Vercel 공개 링크로 제출(로그인 없이 열람 가능).

**비목표**
- 실제 결제·충전·로그인·회원 연동 (심사 가이드상 컬쳐랜드 내부 개발 영역).
- 실시간 AI/LLM 연동 (필수 아님, API 키 노출 위험).
- GS25·교보문고 등 3번째 이후 사용처 (P2, 시간 남으면).

**반목표 (기술적으로 돌아가도 실패)**
- 공식 정보와 다른 수치를 확정처럼 표시.
- 실제 제휴 정보와 가상 시연 데이터가 구분되지 않음.
- 안내만 원하는 사용자에게 처음부터 PIN 전체 입력을 요구.
- 18자리 상품권 사용자에게 "사용 불가"로 끝내버림(대체 공식 경로 존재).
- 상품권 PIN·개인정보·API 키를 저장소/데모에 포함.

## 3. 제약

- 심사: 개발량·기술 복잡성 가점 없음. 화면·흐름의 구체성·정확성 중심(정확성 25 / 편의성 20 / 연결성 20 / 완성도 15 / 앱·PC 10 / AI 10).
- 앱 적용 우선 → 모바일 폭 기준. PC에서 열면 가운데 폰 프레임.
- 브랜드: 제공된 `컬쳐랜드 에셋 및 자료.zip` 에셋만 사용. 로고 색 `#FF3838` / `#000000` / `#FFFFFF`. 빨강·검정 배경 위 로고 금지(BI 가이드 부적절 예).
- 18자리 문화상품권은 발행사가 (주)문화상품권(별개 회사) → 해당 분기 화면에 컬쳐랜드 로고·캐릭터를 쓰지 않고, "타 발행사 공식 경로"로 표기.
- 캐릭터 PNG 원본은 3840×2160, 최대 64MB → 잘라내고 WebP/PNG 축소 후 사용.

## 4. 사용자 흐름 (결정됨)

```
① 사용처 검색 ─▶ ② 상품권 종류 확인 ─▶ ③ 가능 여부·조건 ─▶ ④ 맞춤 사용 방법
   (이름/카테고리/        (컬쳐랜드상품권 /       (온·오프라인 배지,       (단계 체크리스트,
    자연어 문장)           교환권 / 잘 모르겠어요)   수수료·조건·출처)        오류 해결, 다음 행동)
                              │
                              └▶ ②-a 구분 도우미 (자릿수 + 발행사·명칭 확인, PIN 전체 안 물음)
```

### ① 사용처 검색
- 문구: "문화상품권, 어디에서 쓰고 싶으세요?"
- 입력: 텍스트(사용처명 또는 자연어 문장), 카테고리 칩(온라인쇼핑·편의점 등), 인기 사용처.
- 자연어 처리는 **규칙 기반 키워드 매칭**(별칭 사전: 네이버/naver/스마트스토어/N페이 → 네이버쇼핑, 씨유/편의점/CU → CU). AI 미연동임을 설명자료에 명시.
- 결과 없음: "아직 안내 정보가 없는 사용처예요" + 공식 사용처 안내 링크 + 시연 가능한 사용처 제안.

### ② 상품권 종류 확인
- 사용처 맥락 유지(상단에 "네이버쇼핑 · 온라인").
- 확정 문구 대신 "Npay를 통한 사용 경로가 있어요. 갖고 계신 상품권을 확인해 볼까요?"
- 선택지: 통합형 컬쳐랜드상품권 / 오프라인 전용 컬쳐랜드상품권 / 교환권 / 18자리 문화상품권 / 잘 모르겠어요.
- **②-a 구분 도우미**: 12자리 교환권, 16자리 컬쳐랜드상품권, 18자리 지류·온라인 문화상품권 예시 이미지(가상 번호) + "발행사와 상품권에 적힌 이름도 확인하세요". 자릿수는 단서일 뿐 확정 아님. 헌혈기념품 등 12자리 예외 있음 안내.
  - 끝맺음: 사용자가 내 상품권과 닮은 예시 카드를 탭하면 그 종류로 ③ 진행. 그래도 모르면 "그래도 모르겠어요" → 고객센터(1577-2111) + 받은 메시지의 발행사명 확인법 안내. 숫자 입력은 받지 않음. *(내 판단)*

### ③ 가능 여부·조건 (사용처 × 상품권 종류별로 내용이 달라짐)

| 사용처 | 상품권 | 결과 | 핵심 조건 |
|---|---|---|---|
| 네이버쇼핑 | 16자리 컬쳐랜드상품권 | 사용 가능(전환 경유) | 컬쳐캐쉬 충전 → Npay 전환, 안내 수수료 6%(최종 확인 필요), 최소 1,000원, 휴대폰 본인인증, 명의 일치, 전환 후 취소 불가 |
| 네이버쇼핑 | 오프라인 전용 컬쳐랜드상품권 | 이 경로 불가 | 컬쳐캐쉬 충전 불가 안내 → "CU에서 쓰기" 버튼으로 오프라인 사용처 연결 |
| 네이버쇼핑 | 12자리 교환권 | 교환 먼저 | 교환소에서 교환 → **수령한 상품권 종류를 다시 확인**(② 재선택) → 해당 경로 |
| 네이버쇼핑 | 18자리 문화상품권 | 다른 공식 경로 있음 | 컬쳐랜드 충전 불가. (주)문화상품권에서 Npay 직접 전환, 수수료 6.5%, 일 20만·월 50만 원 한도 |
| CU | 통합형 컬쳐랜드상품권 | 사용 가능(2가지 방법) | ⓐ 상품권 자체 바코드: 잔액 확인 → 바코드 제시 → 결제 ⓑ 앱 바코드: 사용 가능한 컬쳐캐쉬 잔액 필요 → 앱 로그인 → 홈 → 바코드결제 → 오프라인 제휴처 선택 → 바코드 확인 → 결제. 일부 매장 제한 가능 → "방문 전 확인" 안내. 제한 품목(담배·각종 상품권·교통카드 충전 등) |
| CU | 오프라인 전용 컬쳐랜드상품권 | 사용 가능(상품권 바코드만) | 충전 불가, 지정된 CU 매장에서 상품권 바코드로 결제. 제한 품목 동일 |
| CU | 12자리 교환권 | 교환 먼저 | 교환 후 수령한 상품권 종류 재확인 → 해당 CU 경로. 모든 교환권이 CU 결제 가능 상품권이 된다고 가정하지 않음 |
| CU | 18자리 문화상품권 | 미확인 | "미확인" 배지 + 발행사 공식 안내 링크, 확정 안내 안 함 *(내 판단)* |

- 수수료 계산기: 16자리 경로는 **6% 하나만** 쓰고 "과거 공지와 차이" 배지(2023-12-21 공지: 2024-01-01부터 6.5%, 현재 공식 화면은 6%) 표시. 9,350P(6.5%)는 18자리 경로 화면에서만 표시. 입력 금액 바꾸면 즉시 계산. *(내 판단)*
- 출처 URL이 마감까지 비어 있으면 해당 카드는 빼지 않고 "미확인" 배지로 출시. *(내 판단)*
- 모든 카드 하단: `출처: <출처명> · 확인일 2026.11.11 · 원문 보기`.

### ④ 맞춤 사용 방법
- 번호 매긴 단계 체크리스트(사용자가 체크 가능). 교환권이면 맨 앞에 "교환" 단계 추가하고, 교환 후 "받은 상품권 종류 확인하기"로 ②에 돌아감(사용처 유지).
- 네이버쇼핑(16자리): 1) 컬쳐랜드 앱 충전(PIN 입력 또는 상품권 속 바로충전 링크) 2) Npay 포인트 전환 3) 네이버쇼핑 결제 시 포인트 사용.
- CU: 방법 ⓐ/ⓑ 탭으로 전환(오프라인 전용은 ⓐ만). 결제 전에 제한 품목 먼저 표시.
- 보조 버튼: "번호가 인식 안 돼요" → 해결 안내(자릿수·종류 재확인, 교환권 여부, 고객센터 1577-2111).
- 주 버튼: "지금 충전하러 가기"(시연용 가짜 화면으로 이동, "시연 화면" 표시).
- 하단: "다른 사용처도 찾아보기"(① 으로, 상품권 종류 기억 유지 → 추가 검색 감소).

## 5. 앱 적용 구상 (심사 10점)

- 진입 위치 1: 컬쳐랜드 앱 홈 상단 "컬쳐캐쉬" 탭 아이콘 그리드(바코드 결제·전환·쇼핑…) 옆 "사용처 찾기".
- 진입 위치 2: 상품권 수신 직후(알림톡/바로충전 링크 랜딩)에서 "이 상품권 어디서 쓰지?".
- 시제품 첫 화면에 위 진입 위치를 보여주는 홈 목업 1장(에셋 기반 단순화) 포함.
- 홈·상품권 수령 직후 화면에는 "앱 적용 제안 목업" 라벨을 붙인다. 실제 컬쳐랜드 앱과 연동된 것처럼 표현하지 않는다.

## 7. 구현 방식 (내가 정한 기본값)

- Vite + React, 정적 SPA. 라우터 없이 화면 상태(useState) 전환. 데이터는 `src/data.js` 한 파일.
- 실제 정보와 가상 시연 데이터 구분: 가상 요소(예시 PIN, 잔액, 가짜 충전 화면)에 "시연용" 라벨.
- 배포: Vercel 정적 배포, Production URL 제출, Deployment Protection 끔.
- 테스트: 키워드 매칭 + **모든 상품권 유형 × 사용처 조합**의 분기 결과 테스트(빠진 조합 없음 검증).
- 검증: 모바일 폭(360·390px) 화면 확인, Vercel production 링크를 비로그인 브라우저로 열어 전체 흐름 확인.

## 8. 제출물

설명 자료 원고는 사용자가 작성 완료(5쪽). 빌더 범위 아님. 단 가이드 필수 항목 중 원고에 없는 것: 앱 적용 구상, AI 활용 과정·검증, 구현 범위 vs 미구현 구분 → 사용자에게 보완 권고.


- 화면 시연: Vercel 링크(필수 1가지 충족).
- 설명 자료(5쪽 이내): 문제·대상 / 기획 의도·구현 내용 / 주요 기능·핵심 화면 / 앱 적용 구상 / AI 활용 과정·정보 출처 / 구현 범위 vs 미구현 항목.
- AI 활용 기록: ChatGPT로 사용자·흐름 조사, Claude로 공식 페이지 대조(6.5% 검색 요약 → 원문 6% 정정 사례 포함), 화면 구현.

## 9. 빌더에게 맡기는 것

- 시각 디자인 세부(간격, 아이콘), 캐릭터 배치 위치, 문구 미세 조정.
- 홈 목업의 재현 정도(에셋 범위 내 단순화).
